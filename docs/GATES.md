# Landfall Gates

A **gate** is a short reference segment across the coastline. When a storm
track crosses a gate, the crossing is attributed to that gate's ID, giving a
stable coastal index that is independent of political boundaries and
comparable across storms and decades.

The gate system is a **standalone, swappable module**. The core pipeline
consumes only a validated `GateSet`; it neither knows nor cares whether that
came from the built-in generator or from your own file.

---

## Substituting your own gate set

Two steps. No code changes.

**1.** Put your gate file somewhere readable.

**2.** Point the config at it:

```yaml
# config/pipeline.yaml
gates:
  override_path: /path/to/my_proprietary_gates.geojson
```

**3.** Rebuild, re-validate, and re-execute the notebook:

```bash
python -m hutrackdb build
```

```bash
python -m hutrackdb qa
```

```bash
python -m nbconvert --to notebook --execute --inplace notebooks/eda_validation.ipynb
```

That's it — a configuration change, no code edited. When `override_path` is set
the built-in generator is bypassed entirely and `calibration.gate_spacing_km` is
ignored. The `gate_id` values you supply are preserved verbatim into
`landfalls.gate_id` and the `landfall_gates` table.

This path is verified end to end: a 12-gate proprietary set was substituted
alongside a coastline with entirely different column names, and build, QA and
the notebook all ran clean. The notebook prints the gate set origin under
**SWAPPABLE INPUTS USED FOR THIS BUILD**, so you can confirm your set is the one
in force:

```
gate set  : override:my_gates.geojson  (12 gates)
            ^ user-supplied gate set in force
```

> Keep `gate_id` values **stable across releases** — they are the join key
> downstream consumers will build on.

## Gate interchange format

Any format geopandas can read: `.geojson`, `.gpkg`, `.shp`, `.parquet` — or a
`.csv` with explicit endpoint columns.

### Required

| Column | Type | Meaning |
|---|---|---|
| `gate_id` | string | Stable unique identifier. Any string. Must be unique and non-null |
| `geometry` | LineString | A line **crossing the shoreline**, 2+ vertices, WGS-84 (EPSG:4326) |

For CSV, supply `lon1`, `lat1`, `lon2`, `lat2` instead of `geometry`.

### Optional (passed through when present)

| Column | Type | Meaning |
|---|---|---|
| `gate_name` | string | Human-readable label |
| `region` | string | Grouping label — state, basin, reach, whatever suits you |
| `sort_order` | integer | Along-coast ordering. Defaults to file order |

### Validation

On load, the gate set is checked for: required columns present, non-empty,
unique non-null `gate_id`, all geometries non-empty LineStrings, and a CRS
present. Any violation raises `GateError` with a message naming the problem —
the pipeline will not run on a malformed gate set.

### Minimal examples

**GeoJSON**

```json
{
  "type": "FeatureCollection",
  "features": [
    {
      "type": "Feature",
      "properties": {
        "gate_id": "TX-CORPUS-01",
        "gate_name": "Corpus Christi approach",
        "region": "Texas Coastal Bend",
        "sort_order": 1
      },
      "geometry": {
        "type": "LineString",
        "coordinates": [[-97.55, 27.62], [-97.05, 27.72]]
      }
    }
  ]
}
```

**CSV**

```csv
gate_id,gate_name,region,sort_order,lon1,lat1,lon2,lat2
TX-CORPUS-01,Corpus Christi approach,Texas Coastal Bend,1,-97.55,27.62,-97.05,27.72
TX-MATAGORDA-02,Matagorda Bay approach,Texas Coastal Bend,2,-96.60,28.35,-96.10,28.55
```

## The default gate set

Generated by the built-in `uniform` generator when no override is set.

- **Basis:** Natural Earth 1:10m Admin-1 boundaries (public domain), the same
  source used for the land polygon — so gates and landfall geometry can never
  disagree about where the shoreline is.
- **Spacing:** `calibration.gate_spacing_km`, **50 km** (PI-confirmed
  2026-08-05).
- **Construction:** each gate is centred on a coastline vertex and oriented
  **perpendicular to the local shoreline trend**, extending 25 km to seaward
  and 25 km to landward, so a track crossing the shore there also crosses the
  gate.
- **Coverage:** the countries listed in `gates.countries` — by default the US,
  Mexico, and the Caribbean/Canadian coasts that Atlantic storms traverse.
- **Result:** **5,007 gates**, region-labelled with the adjacent admin unit.

Gate IDs are `G00000`, `G00001`, … in generation order.

### Changing the default spacing

```yaml
calibration:
  gate_spacing_km:
    value: 25.0
    status: confirmed
    confirmed_by: <your name>
    confirmed_on: 2026-08-05
    source: >
      Why this value was chosen and who approved it.
```

The `status`/`source`/`confirmed_by` keys are **mandatory**. The pipeline
refuses to start if a parameter it uses lacks recorded provenance — see the
Data Integrity section of the [README](../README.md).

## How a gate is assigned

For each landfall, in order:

1. **True gate crossing** — a gate whose geometry the crossing segment
   actually intersects. If several, the one nearest the landfall point.
2. **Fallback** — the nearest gate to the landfall point.

`gate_distance_km` records the geodesic distance from the landfall to the
assigned gate, so a fallback assignment is **visible** rather than
indistinguishable from a real crossing:

```sql
-- landfalls whose gate was a fallback rather than a true crossing
SELECT * FROM landfalls WHERE is_landfall AND gate_distance_km > 0;
```

## Exporting the default set as a starting point

```bash
python -m hutrackdb gates --export my_gates.geojson
```

Writes the current gate set in the interchange format. Edit it, or use it as a
template, then set `gates.override_path`.
